From a factor chain to HJB

A worked example. Everything here uses the method from the main page unchanged — factor graphs, variable elimination, and constraints as +∞ factors — applied to a problem whose variables form a chain in time. It ends by specializing the result to one particular problem, where the remaining work turns out to be calculus rather than optimization.

Cut time into steps · Eliminate from the right · Let the step shrink · Specializing to a particular problem

Everything so far had finitely many variables. Optimal control does not: the thing being chosen is a whole trajectory. Take

infx(·), u(·)   [   φ(x(T)) + ∫0T ℓ(x(t), u(t)) dt   ]
subject to    ẋ = f(x, u),    x(0) = x0

One letter is doing double duty here: in this section f is the dynamics, not a cost. The costs are ℓ per unit time and φ at the end. Nothing is assumed about the form of any of the three.

The tempting move is to invent a special continuous factor graph. It is not necessary. Put the ordinary machinery on a time mesh, run the same elimination, and then let the mesh spacing go to zero — that way you can see exactly which parts survive the limit.

Cut time into steps

Chop [0, T] into N intervals of length Δt, giving times t0, …, tN and variables xk, uk. Over one tiny interval the dynamics say

xk+1 ≈ xk + Δt · f(xk, uk)

That is a rule about which triples (xk, uk, xk+1) are allowed — a constraint. And we already know how to put a constraint in a graph: make it an +∞ factor.

dk(xk, uk, xk+1) = I (   xk+1 = xk + Δt · f(xk, uk)   )

The cost accrued over that interval is a second factor on the same step:

ℓk(xk, uk) = Δt · ℓ(xk, uk)

So the whole trajectory problem is an ordinary finite factor graph problem, with every variable carrying inf:

infu₀, x₁, …, uN−1, xN   [   φ(xN) + Σk ( ℓk + dk )   ]

x0 is given, so it is not a variable. The graph is a long chain of identical stages: states along the spine, and at each step a control together with its two factors — the cost ℓk and the dynamics dk.

Every variable carries inf, so there is no operator-order drama in this problem at all. The order is ours to pick purely for structural efficiency.

Eliminate from the right

Start at the far end. Keep xN−1 symbolic and eliminate everything to its right:

VN−1(xN−1) = infuN−1, xN [   ℓN−1 + dN−1 + φ(xN)   ]

Here the +∞ factor does real work. Given xN−1 and uN−1, exactly one value of xN escapes the infinite penalty, so the inner inf over xN is not a search — it just substitutes:

VN−1(x) = infu [   Δt · ℓ(x, u) + φ( x + Δt · f(x, u) )   ]

Which is precisely the elimination move: collect the factors touching the variables being removed, apply inf, keep the boundary symbolic. The boundary here is the single state xN−1, so what comes back is a new unary factor. Do it again, and again:

Vk(x) = infu [   Δt · ℓ(x, u) + Vk+1( x + Δt · f(x, u) )   ]

That recursion is Bellman's, and we did not derive it — we only eliminated variables right to left. Notice why this order is the good one: at every step the boundary is a single state. It never grows, so the factors never grow, and a chain of a million steps costs a million cheap eliminations.

Let the step shrink

Now send Δt → 0. The number of factor nodes runs off to infinity, and the discrete list V0, V1, …, VN is replaced by one continuously indexed symbolic factor V(t, x). A single infinitesimal elimination step reads:

V(t, x) = infu [   Δt · ℓ(x, u) + V( t + Δt,   x + Δt · f(x, u) )   ]

Expand that new factor to first order:

V(t + Δt,   x + Δt·f) = V(t, x) + Δt · ∂V/∂t + Δt · ∇Vᵀ f(x, u) + o(Δt)

Substitute it in. V(t,x) cancels from both sides, ∂V/∂t does not depend on u so it comes out of the inf, and dividing by Δt and letting it vanish leaves:

0 = ∂V/∂t + infu [   ℓ(x, u) + ∇V(t,x)ᵀ f(x, u)   ],     V(T, x) = φ(x)

The Hamilton–Jacobi–Bellman equation, with the terminal factor φ surviving as the boundary condition.

No new optimization mechanism was introduced anywhere along the way:

finite factor chain  →  backward elimination  →  Bellman recursion  →  Δt → 0  →  HJB

The value function is the symbolic boundary factor. Bellman's recursion is elimination along the chain. HJB is that same elimination written in the continuum limit — a differential statement about how one boundary factor turns into the next.

Exact is not the same as cheap. Each Vk is a whole function of the state, so unless the eliminations happen to keep landing inside a family you can write down with finitely many numbers, storing the boundary factor is itself the hard part. That is the same cost question as before — how big does the boundary factor get — asked about a chain that never ends.

Specializing to a particular problem

HJB above holds for whatever f, ℓ and φ you started with. What it does not tell you is how to write V down. That was the caution at the end of the last section: the boundary factor is a whole function of the state, and carrying it around is the real work.

So pick a problem and ask whether the boundary factor stays inside a family you can store with finitely many numbers. The classical choice is linear dynamics with quadratic costs:

ẋ = Ax + Bu,     ℓ(x, u) = xᵀQx + uᵀRu,     φ(x) = xᵀPTx

Take R positive definite, so the minimization over u has a finite answer, and Q and PT positive semidefinite so costs are never negative.

Everything from here on is substitution and calculus. The optimization was already spent getting to HJB; nothing below reasons about factors, elimination order, or inf versus sup again.

Guess that the family closes

The terminal factor φ is quadratic in x. If one elimination step sends a quadratic boundary factor to another quadratic boundary factor, then every V along the way is quadratic and the guess is self-consistent. So try

V(t, x) = xᵀ P(t) x

with P(t) symmetric. If it works, the entire infinite-dimensional boundary factor is carried by the finitely many numbers in one matrix — which is the whole reason this case is the one everybody solves.

Differentiate

Two derivatives are needed, and both are immediate:

∂V/∂t = xᵀ Ṗ(t) x,      ∇V(t, x) = 2 P(t) x

Substituting them into the bracket inside HJB:

ℓ(x,u) + ∇Vᵀ f(x,u) = xᵀQx + uᵀRu + 2xᵀP(Ax + Bu)

Only two of those terms contain u. Minimize them the way you would minimize anything else — set the derivative to zero:

∂/∂u [   uᵀRu + 2xᵀPBu   ] = 2Ru + 2BᵀPx = 0   ⇒   u* = −R⁻¹BᵀPx

Because R is positive definite this is a genuine minimum, not just a stationary point. Putting u* back in and collecting terms:

infu [   ℓ + ∇Vᵀ f   ] = xᵀ (   Q + AᵀP + PA − PBR⁻¹BᵀP   ) x

Match coefficients

HJB now says that for every x,

0 = xᵀ (   Ṗ + AᵀP + PA − PBR⁻¹BᵀP + Q   ) x

A symmetric quadratic form that vanishes for every x has a zero matrix, so the bracket itself must be zero:

−Ṗ = AᵀP + PA − PBR⁻¹BᵀP + Q,     P(T) = PT

The Riccati differential equation. Integrate it backwards from T and you have P(t), and with it the boundary factor at every time.

The minimizer was computed along the way, so the control comes for free:

u*(t, x) = −R⁻¹BᵀP(t) x

A linear feedback law: measure the state, multiply by a matrix, apply it.

What this section was and was not

Read back over it. There is no factor graph, no boundary, no elimination order, no inf traded against a sup — only a guessed form, one derivative set to zero, and coefficients matched to produce a differential equation. The optimization content lives entirely in the previous section, and it is the same content for every choice of f, ℓ and φ.

Change the problem and HJB does not change; only the answer to “does the boundary factor stay writable?” does. That question has nothing to do with optimization, and for most problems the answer is no — which is why the general case is approximated numerically rather than solved the way this one is.
