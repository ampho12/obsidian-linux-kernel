Optimization by Factor Graphs

1. The factor graph · 2. Variable elimination · 3. Order of elimination · 4. Handling constraints · 5. Pricing a constraint · 6. Duality · 7. The method in one page · Worked examples

Optimization is the process of choosing one option out of many. Say you are buying a mattress. You lie on a few of them in the shop and each one earns a verdict — this one wrecks your back, that one is too soft, the third is decent. You are scoring options and keeping the best.

That is all a cost function is. Write x for a mattress and f(x) for how badly you slept on it. Lower is better, so find the best mattress becomes find the x that makes f(x) smallest. We write that as:

infx   f(x)

inf is short for infimum. Read the whole thing as “the lowest value of f you can reach by choosing x.” It is used instead of min because min promises that some x actually attains the best value, and sometimes none does: for x > 0, the cost f(x) = x gets arbitrarily close to 0 without ever reaching it. inf is the greatest lower bound, so it always exists.

Worth keeping apart: the value infx f(x), and the argument argminx f(x) that achieves it. Both will be needed later.

Sometimes, even though you like a mattress a lot, it is not something you can buy. The bed frame is only so tall, so anything thicker than 30 cm is out. You will only buy from the two or three brands you trust. And the frame is exactly 150 cm wide, so the mattress has to be too. These are constraints: rules that rule options out before comfort is even considered.

  • At most — height ≤ 30 cm, an inequality constraint.
  • One of these — brand ∈ {A, B, C}, a set constraint.
  • Exactly — width = 150 cm, an equality constraint.

Constraints come back in section 4, once there is machinery worth pointing at them. Set them aside for now.

Two variables at once

A mattress is one choice. Most real problems are many choices at once. Suppose there are two variables, x and y, and a single cost to minimize over both:

F(x,y) = (x − 1)² + (y − 4)²

Rather than trying values by hand, differentiate and set the derivatives to zero:

∂F/∂x = 2(x − 1) = 0  ⇒  x = 1
∂F/∂y = 2(y − 4) = 0  ⇒  y = 4

Notice that the two equations came out completely unrelated. x never appears in y's equation, so each can be solved on its own. This cost is separable: two one-variable problems that happen to be written on the same line.

Now add a single term to it:

F(x,y) = (x − 1)² + (x − y)² + (y − 4)²

Same strategy, same two derivatives — but they no longer come apart:

∂F/∂x = 2(x − 1) + 2(x − y) = 0
∂F/∂y = −2(x − y) + 2(y − 4) = 0

Each equation now mentions the other variable, so neither can be solved alone. They have to be solved together, which gives x = 2, y = 3, and F = 1 + 1 + 1 = 3.

One extra term changed the character of the problem entirely. Nothing about the size changed — still two variables — but (x − y)² is a place where x and y interact, and interaction is what stops you from working on them separately.

With two variables you can just solve the coupled pair by hand. With fifty you cannot — but you also rarely have to, because real costs couple only a few variables at a time. So the useful question becomes: which variables actually interact, and where? There is a way to picture exactly that. It is called a factor graph.

1. The factor graph

Look again at the two costs above. Each is a sum of terms, and each term looks at only some of the variables. Draw one node per variable, one node per term, and connect them when the term depends on the variable.

One connected chain. The middle box is the interaction, drawn as the thing that joins them. The whole notation is three pieces:

  • Circles are variables — the things you get to choose.
  • Rounded boxes are factors — the individual terms of the sum. Each is just a small function.
  • An edge means one thing only: “this factor depends on this variable.” No formulas, no numbers, no direction.

In general the cost is a sum of factors, each looking at a handful of variables:

F(x₁, …, xₙ) = Σα fα(xα)

α indexes the terms, and xα means “the few variables that term α actually looks at.”

The running example

Take the coupled cost from the introduction and insert one more variable in the middle, so y no longer reaches the anchor at 4 directly:

F(x,y,z) = (x − 1)² + (x − y)² + (y − z)² + (z − 4)²

Read left to right: x should be near 1, x and y should be near each other, y and z should be near each other, z should be near 4. A tug-of-war along a chain, and it draws as one:

The shape matters more than the formulas: it is a chain, and no factor touches both x and z. That absence is what the next section exploits.

2. Variable elimination

In the introduction we solved the coupled problem by writing down every derivative and setting all of them to zero at once. That works, but it treats every variable as equally entangled with every other: one big simultaneous system, all n equations solved together. The graph says the entanglement is not uniform. Most variables touch only a few factors, and everything else in the cost is irrelevant to them.

Variable elimination exploits exactly that. Rather than solving for all variables simultaneously, remove them one at a time, and when removing one, look only at the factors it touches. The licence to do this is:

infx,y F(x,y)  =  infx [   infy F(x,y)   ]

Minimizing jointly is the same as minimizing over y first while pretending x is a fixed constant, and then minimizing what is left over x. The inner step still depends on x, so it leaves behind a function of x rather than a number.

The recipe. To eliminate a variable, collect every factor attached to it, apply inf over that variable, and keep its neighbours symbolic. The result is one new factor on those neighbours.

The graph earns its keep in the first three words: every factor attached to it. Factors that do not touch the variable are constants for this step and get carried along untouched.

Eliminating one variable

Eliminate y from the chain. Attached factors: fxy and fyz — two of the four. Surviving neighbours, called the boundary: {x, z}.

m₁(x,z) = infy [  (x − y)² + (y − z)²  ]

This is the same differentiation as before, but on two terms instead of four. Setting the derivative in y to zero gives y = (x + z)/2 — split the difference — and substituting back gives a closed form:

m₁(x,z) = ½ (x − z)²

y and its two factors are gone. One new factor m₁ sits in their place, joining x directly to z:

The problem is smaller and exactly equivalent — nothing was approximated. Note what the new factor is not: it is none of the original terms, and it did not exist before. Elimination creates a factor on the boundary. That is the whole mechanism, and everything remaining on this page is this step with different fillings.

Repeating until nothing is left

Each pass removes one variable and leaves a strictly smaller problem of the same kind, so just do it again. Peel the chain: y, then z, then x.

start
infx,y,z [ fx + fxy + fyz + fz ]
eliminate y — factors fxy and fyz
m₁(x,z) = ½ (x − z)²
eliminate z — factors m₁ and fz
m₂(x) = infz [ ½(x − z)² + (z − 4)² ] = ⅓ (x − 4)²
eliminate x — factors fx and m₂
F* = infx [ (x − 1)² + ⅓(x − 4)² ] = 9/4 = 2.25

That is the value. The argument comes from unwinding in reverse, using the minimizer recorded at each step:

x* = 7/4
z* = (x* + 8)/3 = 13/4
y* = (x* + z*)/2 = 5/2

Check by direct substitution — all four terms land equal, so the tug-of-war settles into a perfect compromise:

(7/4 − 1)² = 9/16
(7/4 − 5/2)² = 9/16
(5/2 − 13/4)² = 9/16
(13/4 − 4)² = 9/16
total = 36/16 = 9/4 ✓

Never at any point were three variables handled at once. Compare the alternatives on a chain of n variables with K candidate values each: checking every combination costs Kⁿ, while elimination costs n passes of K². Ten variables at a hundred values each is the difference between 10²⁰ and 10⁵.

3. Order of elimination

We eliminated y, then z, then x — but nothing forced that. Six orders were available. Does the choice matter?

infx infy F = infy infx F = infx,y F

When every variable is minimized, not for the answer. Two infs commute, so any order returns the same minimum. It matters for cost: eliminating a variable with many neighbours creates a new factor over all of them, which can be far larger than anything in the original problem. Choosing an order that keeps boundaries small is the entire practical art.

When not every variable is minimized

So far every variable was yours to minimize. Often some are not: an adversary chooses them, or nature does, or they are prices set against you. Those variables are maximized, written sup — the mirror image of inf.

Two sups commute for the same reason two infs do, so nothing changes yet. What breaks is mixing them. Once both appear, a factor graph alone can no longer state the problem: each variable must also carry an operator, and those operators must be written in a definite order.

O1x₁ O2x₂ … Onxₙ   [   Σα fα(xα)   ],    Oi ∈ { inf, sup }

Unpacked, that is only: a cost written as a sum of factors, plus a list saying who optimizes what, in what order. The clearest way to see what the order does is to write it as nested loops — outermost operator, outermost loop: 

infx supz F

  best = +infinity
  for x in X:                    # outer
      inner = -infinity
      for z in Z:                # runs once per x
          inner = max(inner, F(x, z))
      best = min(best, inner)    # x selects only now
  return best

Two things fall out of this. The inner loop runs once for every setting of x, so every z is evaluated against a fixed, already-known x — that is what it means for z to reply to x. And x's own selection is the last line of the loop body, after the inner loop has finished: x is enumerated first but chooses last. Being outermost does not mean deciding early. It means having to decide with a single value that cannot depend on z, while z gets a different reply for every x.

Flip the nesting and the roles swap exactly: 

supz infx F

  best = -infinity
  for z in Z:                    # outer
      inner = +infinity
      for x in X:                # runs once per z
          inner = min(inner, F(x, z))
      best = max(best, inner)
  return best

A longer prefix such as infx supz infy F nests three deep in the same way. Evaluation always finishes the innermost loop first — which is why elimination proceeds inside out: y, then z, then x.

Why mixing them breaks the freedom

Let x, z ∈ {0, 1} and let F(x,z) = 1 if x = z, otherwise 0. x wants it small; z wants it large.

F z = 0 z = 1
x = 0 1 0
x = 1 0 1

Run the first loop on it. For x = 0 the inner max over z is max(1, 0) = 1; for x = 1 it is max(0, 1) = 1; the outer min over those is 1. Whichever x is fixed, z has a reply that matches it.

Now run the second. For z = 0 the inner min over x is min(1, 0) = 0; for z = 1 it is min(0, 1) = 0; the outer max is 0. Whichever z is fixed, x has a reply that dodges it.

supz infx F = 0   ≠   infx supz F = 1

Same table, same two operators, same four numbers visited — only the nesting changed, and the answer changed with it.

So the four cases are:

  • inf inf — commutes. Order is free; choose it for cost alone.
  • sup sup — commutes, by the same argument.
  • inf sup — the minimizer commits first, the maximizer replies. This is the larger of the two mixed values.
  • sup inf — the maximizer commits first, the minimizer replies. This is the smaller.
supz infx F  ≤  infx supz F

Always true, in that direction: committing first can never help you. So swapping unlike operators is not the harmless bookkeeping of two infs — it changes the problem, and generally only gives a bound.

4. Handling constraints

Back to the bed frame. The mattress had to be under 30 cm, from a short list of brands, exactly 150 cm wide — rules sitting alongside the question of comfort, and seemingly a different kind of object from it. They need not be. Allow a factor to take the value +∞, and a hard rule becomes an ordinary factor:

Ih(x) = 0  if h(x) = 0,     +∞ otherwise.

Any x that breaks the rule now costs +∞, so the minimization will never pick it. That turns a constrained problem into a plain sum:

infx f(x)  subject to h(x) = 0   =   infx [   f(x) + Ih(x)   ]

Both sides have the same answer, but the right-hand side is a plain factor graph, with the constraint drawn as just another box:

The same trick covers all three flavours from the introduction: an inequality charges +∞ as soon as it is violated, a set constraint charges +∞ outside the set. Objective and constraints now live in the same graph and obey the same elimination recipe.

What if the variable is being maximized?

Nothing about +∞ is special — what matters is that it is unreachably bad for a minimizer. Hand the same factor to a sup and it inverts: a maximizer would hunt down the infeasible points precisely because they score +∞. The barrier has to be whatever the operator that owns the variable is trying to avoid, so for sup it points the other way:

−Ih(x) = 0  if h(x) = 0,     −∞ otherwise.
supx f(x)  subject to h(x) = 0   =   supx [   f(x) − Ih(x)   ]

Same factor, same graph, opposite sign. Stated once for both cases: a constraint factor takes the value its variable's operator is trying to avoid — +∞ against inf, −∞ against sup.

One caution once a graph holds both operators. A sum containing both +∞ and −∞ has no defined value, so a single barrier factor cannot serve two variables with opposite operators. When a constraint genuinely couples an inf variable to a sup one, choosing which side it restricts is a modelling decision, not a change of notation — and the result is no longer a plain minimax.

5. Pricing a constraint

An +∞ factor is awkward to compute with. There is an exact rewrite that removes the infinity, and it uses the sup from the previous section:

Ih(x) = supλ   λᵀ h(x)

Why is this exactly the indicator? Fix x; then h(x) is simply some vector. If it is zero, every choice of λ gives 0, so the sup is 0. If it is nonzero, scale λ along it and the value grows without bound — the sup is +∞. So the hard wall is reproduced by a new variable that charges for violations, with unbounded prices available. λ is the price, or multiplier.

What sat inside that sup is a function of both variables, so give it a name and treat it as one more factor in the graph:

g(x, λ) = λᵀ h(x)

g is the only new object here. It touches x and λ, it is finite everywhere, and it is what replaces the wall. Substituting it in turns the constrained problem into an operator-annotated factor expression:

p* = infx supλ [   f(x) + g(x, λ)   ]

The bracket is the Lagrangian L(x, λ). Note the order: infx supλ, inherited directly from the rewrite above. Getting it backwards is a different problem, as the four cases warned.

The maximization case mirrors it, exactly as the −∞ barrier did. To hold −Ih we need a price that drives the value down on violation, so the price variable carries inf:

−Ih(x) = infλ   g(x, λ)    ⇒    supx infλ L(x, λ)

Feasible x still gives 0 for every λ; infeasible x lets λ scale against the violation and drive the term to −∞. So the rule is: the price always carries the opposite operator to the variable it constrains.

Which is worth pausing on. Pricing a constraint never yields a same-operator prefix — it manufactures an inf sup or a sup inf every time. Constrained optimization is mixed-operator optimization.

On the graph, the wall became a node: a real variable, carrying sup, joined to x by a finite factor.

6. Duality

What is left is an ordinary two-variable factor graph, and we already know what to do with one of those: eliminate a variable. Keep λ symbolic and eliminate x.

q(λ) = infx [   f(x) + g(x, λ)   ]

That is the elimination recipe verbatim: collect the factors touching x, apply x's operator, keep the boundary {λ} symbolic, record the result as a new factor. The new factor q(λ) has a name — the Lagrangian dual function.

Worked example

Minimize x² + y² subject to x + y = 2. Build the Lagrangian and eliminate both x and y:

L = x² + y² + λ(x + y − 2)

infx [ x² + λx ] = −λ²/4
infy [ y² + λy ] = −λ²/4

q(λ) = −λ²/2 − 2λ

Now maximize that summary over λ:

dq/dλ = −λ − 2 = 0  ⇒  λ* = −2
q(−2) = −2 + 4 = 2

And directly: x = y = 1 gives 1 + 1 = 2. The two agree.

Two paths, two answers

The primal path, infx supλ L(x, λ), respects the original nesting: the inner sup over λ rebuilds the hard constraint factor, and you are back to the indicator of section 4.

The dual path, supλ infx L(x, λ), eliminates x first to get q(λ) and then maximizes it. Often far easier — but it is a different order.

supλ infx L  ≤  infx supλ L     i.e.   d* ≤ p*

This is the sup inf ≤ inf sup inequality again, nothing more. Dualizing is not a cheaper elimination order in the harmless same-operator sense — it swaps unlike operators, so in general it only yields a lower bound. The gap p* − d* is the duality gap; closing it requires extra conditions (convexity plus a constraint qualification), which is what a strong duality theorem asserts.

In the worked example above the gap was zero — but that was a fact to be checked, not a rule to be assumed.

For a constrained sup problem everything reflects. There the primal is supx infλ L, the dual is infλ supx L, and the same single inequality now reads the other way round: the dual is an upper bound on the primal. The direction of a duality gap is not a separate fact to memorise — it follows from which side of sup inf ≤ inf sup your problem started on.

7. The method in one page

  1. Factor. Write the cost as a sum of local terms.
  2. Draw. Connect each term to the variables it touches.
  3. Annotate. Attach inf or sup to each variable, in order.
  4. Eliminate. Remove one variable at a time; keep its boundary symbolic.
  5. Audit. If you swapped inf and sup, name the bound or theorem.

Optimization by factor graphs is repeated construction of symbolic boundary functions. For a variable z with surviving boundary s, build a new factor by applying z's operator while keeping s symbolic:

m(s) = Oz [   local factors involving z and s   ]

Every step above was this formula with different fillings: m₁(x,z) when y was eliminated, m₂(x) when z was, Vk(x) at every step of the control chain, and q(λ) when x was eliminated from the Lagrangian — one move, three costumes.

The same pattern names things far beyond this page: Bellman value functions in dynamic programming, messages in belief propagation, variable elimination in graphical models, Lagrangian duals in convex optimization. What changes between them is only the operator, the boundary, and whether reordering preserved the original problem.
